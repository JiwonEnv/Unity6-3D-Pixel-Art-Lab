# 🧭 5. 기술 선택 가이드

이 프로젝트의 목적은 기술을 만드는 것만이 아니라 **어떤 상황에 선택하고, 무엇을 감수하고, 어떻게 관리하는지**를 남기는 것입니다.
기술마다 같은 형식으로 정리했습니다. 더 자세한 기록은 [Notion 기술 템플릿](https://app.notion.com/p/41310d86fdd580a7af9fd1f146aa43a1)에 있습니다.

## 먼저: 3D 픽셀 배경 자체를 고를까?

| 선택한다 | 선택하지 않는다 |
|---|---|
| 도트 그림체 + 시점 · 시간대 · 날씨 변화가 필요 | 한 장면의 도트 완성도가 최우선 (손 도트가 정확) |
| 배경 볼륨이 커서 손 도트로 다 그리기 어려움 | 고해상도 사실적 화면이 목표 |
| 실사 텍스처 에셋을 도트 화면에 섞고 싶음 | 카메라가 자유롭게 확대 · 회전해야 함 |
| 조명 연출을 실시간으로 바꿔야 함 | 셰이더 · 렌더러 기능을 유지보수할 사람이 없음 |

---

## 🟫 픽셀 카메라

| | |
|---|---|
| **목적** | 3D를 도트 해상도로 그리고, 카메라가 움직여도 픽셀이 흔들리지 않게 |
| **선택** | 직교 카메라로 내려다보는 3D 픽셀 게임 |
| **비추천** | 원근 카메라, 자유 확대 · 회전 |
| **장점** | 정지한 배경 텍셀이 완전히 고정, 스크롤은 부드러움, 저해상도라 효과가 쌈 |
| **단점** | 카메라 연출이 텍셀 격자에 묶임, UI는 따로 그려야 함 |
| **관리** | 흔들림 · 확대는 텍셀 단위로만. 버퍼를 쓰는 효과는 모두 버퍼 해상도로 계산 |

## 🌗 툰 조명

| | |
|---|---|
| **목적** | 연속 명암 대신 끊긴 4단 명암, 그림자는 색으로 |
| **선택** | 도트 · 셀 그림체, 광원마다 다른 색 명암이 필요할 때 (노을 + 횃불) |
| **비추천** | 실사 PBR 목표 (대신 반실사 블렌드), GI · 라이트맵 품질이 중요한 정적 장면 |
| **장점** | 광원마다 단계 제어, 그림자 색으로 시간대 분위기 |
| **단점** | URP Lit의 GI · 반사 프로브를 다시 만들어야 함 |
| **관리** | 그림자는 주변광, 직사광은 더하기만. 단계 값은 `ToonRampStyle` 하나에서 |

## ✏️ 선화

| | |
|---|---|
| **목적** | 물체 테두리에 1픽셀 선, 안쪽 · 바깥 선 세기 따로 |
| **선택** | 물체가 배경에서 또렷이 떨어져 보여야 할 때, 저해상도라 깊이 선만으로 끊길 때 |
| **비추천** | 실사 배경, 고해상도 화면 |
| **장점** | 물체 단위 선 세기, 흔들리는 잎도 선이 따라감 |
| **단점** | 물체마다 ID 컴포넌트, ID · 깊이 패스 비용 |
| **관리** | 새 셰이더도 `LabWind` · `LabVisibility`를 써야 선이 맞음 |

## 🌬 바람

| | |
|---|---|
| **목적** | 정지한 배경에 살아 있는 움직임, 12fps로 끊어 도트 애니메이션처럼 |
| **선택** | 한쪽이 고정된 물체 (나무 · 풀 · 천), 수가 많아 뼈대 애니메이션을 못 쓸 때 |
| **비추천** | 캐릭터와 부딪히며 휘는 풀, 충돌 모양이 바뀌어야 할 때 |
| **장점** | 데이터 없이 셰이더만, 그림자 · 선화와 어긋나지 않음 |
| **단점** | 상호작용 없음, 모든 패스에 같은 정점 함수 필요 |
| **관리** | 종류는 머티리얼이 아니라 렌더러(`WorldSurfaceMotion`)에 |

## 🌧 젖음

| | |
|---|---|
| **목적** | 머티리얼을 바꾸지 않고 날씨 하나로 모든 표면을 젖게 |
| **선택** | 실시간 날씨가 있는 야외 |
| **비추천** | 실내 · 지붕 아래 (가림 판정 없음), 빗물 줄기처럼 방향 있는 표현 |
| **장점** | 텍스처 추가 없음, 발광 부분 제외, 천천히 마름 |
| **단점** | 가려진 곳도 젖음, 재질별 차이가 작음 |
| **관리** | 웅덩이와 같은 `wetness` 값을 씀. 속도는 `WeatherProfile`에서만 |

## ❄️ 눈 · 발자국

| | |
|---|---|
| **목적** | 모델을 따로 만들지 않고 위쪽 면에 눈, 걸으면 발자국 |
| **선택** | 계절 · 날씨가 실시간으로 바뀌는 장면, "덮였다"는 인상이 중요할 때 |
| **비추천** | 깊게 파이는 눈 (테셀레이션 · 높이맵 필요), 실내 |
| **장점** | 모든 물체에 자동, 계단식 적설이 도트와 맞음 |
| **단점** | 두께 · 실루엣 변화 없음 |
| **관리** | 양은 `snowCover`, 모양은 `SnowStyle`, 발자국 위치 규칙은 `terrainOnly` |

## 💧 웅덩이 · 반사

| | |
|---|---|
| **목적** | 비가 오면 웅덩이가 차고 주변이 비침. 보이는 물과 발 물튀김 판정이 같은 자리 |
| **선택** | 넓은 지형에 손 배치가 어려울 때, 비 온 뒤 분위기가 중요할 때 |
| **비추천** | 웅덩이 위치가 레벨 디자인에 쓰일 때, 경사가 심한 지형 |
| **장점** | 맵 전체 자동 배치, 같은 맵이면 위치 고정 |
| **단점** | 반사 카메라 비용 (저해상도 · 초당 20회로 제한), 셰이더와 C# 수식을 같이 고쳐야 함 |
| **관리** | `LabPuddles.hlsl` ↔ `PuddleSurface.cs` 같이 수정. 높이 하한은 `PuddleStyle.minimumHeight` |

## 🌊 물

| | |
|---|---|
| **목적** | 도트에 맞는 계단식 반짝임 · 물가 거품 + 실제 반사 |
| **선택** | 호수 · 연못이 장면의 중심일 때 |
| **비추천** | 흐르는 강 · 폭포 (흐름 방향 없음), 타원이 아닌 복잡한 물가 |
| **장점** | 직교 카메라에서도 진짜 반사, 물 영역을 컴포넌트로 지정 |
| **단점** | 반사 카메라 비용, 물가는 타원만 |
| **관리** | 머티리얼 `Water surface` + 렌더러 바람 모드 4 + `WaterBody` |

## 🏮 생활 조명

| | |
|---|---|
| **목적** | 밤을 등불이 이끌게, 불빛이 살아 있게 |
| **선택** | 밤 · 실내 장면, 생활감이 필요한 마을 · 야영지 |
| **비추천** | 그림자 있는 광원이 수십 개 필요할 때 (파이프라인 직접 제작을 검토) |
| **장점** | 씬마다 조명 목록 관리 없음, 발광 · 빛 · 안개 번짐이 같은 값으로 움직임 |
| **단점** | 그림자 수 제한 (가까운 4개) |
| **관리** | 그림자 예산 포인트 4 × 512. 일렁임 시드는 월드 위치 |

## 🌫 높이 안개 · 빛줄기 · 색 보정

| | |
|---|---|
| **목적** | 직교 카메라에서도 깊이감, 등불 빛줄기, 노을 주홍 → 분홍 → 보라 |
| **선택** | 거리 안개가 평평한 색막이 되는 직교 카메라, 밤 조명 연출 |
| **비추천** | 고해상도 사실적 볼류메트릭 (HDRP가 나음), 프레임 예산 1ms 미만 |
| **장점** | 저해상도라 쌈 (에디터 측정 약 0.3~0.7ms), 시간 누적이 없어 잔상 없음, 구역별 Volume |
| **단점** | 직접 만든 레이마칭 유지보수, 노이즈는 블러로만 줄임 |
| **관리** | 시간대 값은 `TimeOfDayProfile`, 구역 차이는 `PixelAtmosphere` Volume |

## 🧍 캐릭터 가독성

| | |
|---|---|
| **목적** | 디테일한 배경 위에서도 도트 캐릭터가 묻히지 않게, 가려져도 위치를 잃지 않게 |
| **선택** | 배경 디테일이 캐릭터보다 높은 장면, 나무 · 건물이 시야를 가리는 탑다운 |
| **비추천** | 배경이 단순해 캐릭터가 이미 잘 보일 때 |
| **장점** | 배경을 줄이지 않고 캐릭터를 살림, 12fps 포즈가 도트와 맞음 |
| **단점** | 가림막을 종류별로 지정, 빠른 동작에서 포즈가 끊겨 보일 수 있음 |
| **관리** | 가림막 종류는 이름이 아니라 `PlayerOccluder`, 캐릭터 연결은 `LabCharacter` |
