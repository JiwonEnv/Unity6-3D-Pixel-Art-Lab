# 📓 7. 렌더 파이프라인 결정

> PC 게임이라 HDRP를 쓸 수 있었지만 **URP + 직접 만든 렌더러 기능**을 골랐습니다. 전체 근거: [Render-Pipeline-Decision.md](https://github.com/JiwonEnv/Unity6-3D-Pixel-Art-Lab/blob/main/Docs/Render-Pipeline-Decision.md)

## 한 줄 요약

이 그래픽의 뼈대는 **광원마다 직접 계산하는 툰 조명과 픽셀 버퍼 위의 선화**입니다. HDRP는 조명을 엔진 안에서 한꺼번에 합쳐 이 제어가 어렵습니다.

## 비교

| 선택지 | 잘하는 것 | 이 스타일에서의 문제 |
|---|---|---|
| **URP + 렌더러 기능 (선택)** | 광원 함수를 셰이더에서 직접 호출, RenderGraph로 패스 추가, 가벼움 | 볼류메트릭이 없어 직접 만들어야 함 |
| HDRP | 물리 기반 조명, 볼류메트릭 안개 · 빛줄기 | 광원별 툰 계산이 어렵고 업데이트마다 다시 손봐야 할 위험. 볼류메트릭은 시간 누적이라 픽셀 버퍼에서 잔상 |
| Unreal Engine | 고품질 사실적 렌더링 | 지연 렌더링이라 광원별 툰 계산을 넣으려면 엔진 수정 수준 |
| 파이프라인 전체 직접 제작 | 배경 캐싱, 층별 해상도 · 프레임 합성, 그림자 캐싱 | 개발 · 유지보수 비용이 가장 큼. 목표 레퍼런스 Replaced가 이 방식 |

## 직접 만든 것 = 기성 렌더러에 없는 것만

| 필요한 것 | 기성 렌더러에 없는 이유 | 직접 만든 기능 |
|---|---|---|
| 픽셀 버퍼 + 정수 확대 + 서브픽셀 보정 | 렌더 스케일은 있지만 텍셀 스냅이 없음 | `ExplorationCamera` |
| 광원별 툰 램프 · 그림자 색 · 횃불 감쇠 | 기본 조명은 물리 기반 연속 명암 | `LabToonLighting` |
| 물체 단위 1픽셀 선화 | 기본 외곽선 기능 없음 | ID 패스 + 선화 패스 |
| 계단식 애니메이션 | 애니메이터는 매 프레임 보간 | `SteppedAnimator` |
| 캐릭터 가림 해소 | 게임 고유 연출 | 스텐실 · 스캔 패스 |
| 픽셀 단위 빛줄기 · 높이 안개 | URP에 볼류메트릭 없음 | 픽셀 해상도 레이마칭 |

## 장점과 비용

| 장점 | 비용 |
|---|---|
| 그림체를 정하는 값이 모두 우리 코드에 있다 | 셰이더 · 렌더러 기능 · 검증 스크립트를 직접 유지보수 |
| URP 공개 API(RenderGraph)에만 기대 업데이트에 덜 흔들림 | URP 메이저 버전마다 RenderGraph 코드 점검 |
| 필요한 효과만 버퍼 해상도로 계산 | 기성 기능도 스타일에 맞추려면 새로 만듦 |

## 다시 검토할 조건

- 배경 캐싱이나 층별 해상도 합성 없이 목표 프레임(GTX 1060급 1080p 60fps)을 못 지킬 때
- 생활 조명 수십 개에 그림자가 모두 필요해질 때
- URP 업데이트로 렌더러 기능 유지 비용이 커질 때
